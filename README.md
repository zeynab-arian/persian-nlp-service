# Technical Report
## طراحی و پیاده‌سازی سرویس جامع پردازش زبان طبیعی (AI-NLP) برای متون فارسی

**عنوان پروژه:** پیاده‌سازی سرویس ماژولار NLP مبتنی بر AI برای پردازش متون فارسی  
**حوزه:** NLP Service / Persian Text Processing / API-based Architecture

---

## 1. مقدمه (Introduction)

با گسترش اسناد دیجیتال و غیرقابل‌ویرایش نظیر PDFهای اسکن‌شده و تصاویر، نیاز به سامانه‌هایی که بتوانند این داده‌ها را به متن قابل پردازش تبدیل کرده و سپس روی آن تحلیل‌های هوشمند انجام دهند افزایش یافته است. پردازش زبان طبیعی (NLP) به‌عنوان یکی از شاخه‌های کلیدی هوش مصنوعی، ابزارهایی برای اصلاح متن، طبقه‌بندی، استخراج اطلاعات، خلاصه‌سازی و جستجوی معنایی فراهم می‌کند.

پروژه حاضر با عنوان **AI-NLP** با هدف طراحی و پیاده‌سازی یک سرویس جامع و توسعه‌پذیر ایجاد شده است که مجموعه‌ای از قابلیت‌های زیر را در قالب **API** ارائه می‌دهد:
- اصلاح متن (Text Correction)
- طبقه‌بندی متن (Text Classification)
- استخراج/جستجوی دامنه‌محور کلمات کلیدی (Domain-based Keyword Extraction)
- تشخیص متن از تصویر و اسناد (OCR)
- خلاصه‌سازی متن (Summarization)

این ساختار ماژولار باعث می‌شود هر قابلیت به‌صورت مستقل توسعه یافته و هم‌زمان با سایر ماژول‌ها یکپارچه شود. :contentReference[oaicite:1]{index=1}

## 2. اهداف و دستاوردهای پروژه

### 2.1 اهداف اصلی
1) تبدیل داده‌های غیرقابل‌ویرایش (PDF/تصویر) به متن قابل پردازش  
2) ارائه مسیرهای API برای پردازش متن با روش‌های مختلف (مدل لوکال / LLM / HuggingFace)  
3) امکان آموزش مدل طبقه‌بندی از داده کاربر و ارائه پیش‌بینی برای داده‌های جدید  
4) امکان تعریف دامنه و کلیدواژه برای استخراج اطلاعات دامنه‌محور  
5) آماده‌سازی زیرساخت توسعه‌پذیر (Config، ساختار پوشه‌ها، قابلیت Dockerization و …)

### 2.2 دستاوردهای پیاده‌سازی‌شده (بر اساس لاگ توسعه)
- پشتیبانی از ورودی‌های PDF/DOCX/TXT و تصاویر و تشخیص نوع واقعی فایل
- استخراج متن اولیه و OCR برای PDFهای اسکن‌شده/تصاویر
- پیش‌پردازش و پاک‌سازی نویز و استانداردسازی فاصله‌ها
- Chunking متن و خلاصه‌سازی بخش‌بخش
- اتصال به LLM خارجی برای پاک‌سازی/اصلاح متن و خلاصه‌سازی (OpenRouter)
- طراحی APIهای ماژولار و توسعه سرویس‌ها (OCR, Summarizer, Correction, Classification, Extraction)

## 3. معماری سیستم و ساختار پروژه

### 3.1 ساختار پوشه‌ها
ساختار کلی پروژه به شکل زیر است:
- `api/` : routeها و endpointهای FastAPI
- `services/` یا `core/services/` : منطق پردازش ماژول‌ها (OCR، correction، classification، extraction، summarizer)
- `core/` : تنظیمات و پیکربندی (configuration)
- `models/` و `db/` : مدل‌های داده و ساختار ذخیره‌سازی

### 3.2 مدیریت تنظیمات (Configuration)
تنظیمات با استفاده از `pydantic_settings` و فایل `.env` پیاده‌سازی شده است.  
پارامترها شامل:
- محیط اجرا: `APP_ENV` با مقادیر `dev` یا `prod`
- مسیرهای مدل Nevise در dev/prod (vocab و checkpoint)
- تنظیمات دیتابیس MySQL در dev/prod
- تنظیمات اتصال به LLM و سرویس Mistral
- تنظیمات مدل‌های HuggingFace و embedding
- مسیر ذخیره‌سازی داده‌ها (`DATA_PATH`)
- حداقل تعداد نمونه موردنیاز برای هر کلاس در طبقه‌بندی (`MIN_SAMPLES_PER_CLASS = 5`)
- لیست stopwords دامنه‌محور برای پیش‌پردازش متن

#### 3.2.1 انتخاب پویا مسیر مدل Nevise
برای سوییچ بین dev/prod از propertyهای زیر استفاده شده است:
- `MODEL_VOCAB_PATH`
- `MODEL_CHECKPOINT_PATH`

#### 3.2.2 اتصال دیتابیس
ساخت URL به‌صورت پویا بر اساس env انجام می‌شود:
`mysql+pymysql://user:password@host:port/smart`

این طراحی، استقرار پروژه را در محیط‌های مختلف ساده‌تر و قابل کنترل می‌کند.

## 4. ماژول اصلاح متن (Text Correction)

### 4.1 هدف
هدف این ماژول اصلاح خطاهای املایی، نگارشی و دستور زبان فارسی بدون تغییر معنی و محتوای جمله است. ماژول از دو روش پشتیبانی می‌کند:
- **Nevise (لوکال)**: مدل مبتنی بر BERT برای اصلاح املایی
- **LLM-based**: ارسال متن به سرویس LLM و دریافت متن اصلاح‌شده

### 4.2 API
- `POST /correct/`
- ورودی:
  - `text` (Form)
  - `method` یکی از `nevise` یا `llm`
- خروجی:
  - `method`
  - `corrected`
  - `mistakes` (در روش Nevise)

### 4.3 روش Nevise (Local)
در این روش مدل تنها یک‌بار load می‌شود و cache می‌گردد (بهبود کارایی).  
مراحل:
1) نرمال‌سازی متن با Hazm
2) تقسیم متن به جمله‌ها (`get_sentences_splitters`)
3) اجرای مدل اصلاح
4) استخراج تفاوت‌ها و ساخت لیست خطاها (wrong/correct)

### 4.4 روش LLM-based و Prompt
در روش LLM یک prompt سیستم مشخص اعمال می‌شود:
> متن زیر را فقط از نظر املایی، نگارشی و دستور زبان فارسی اصلاح کن و متن اصلاح‌شده را مستقیم بده. هیچ تغییری در جمله یا محتوا نده و چیزی اضافه نکن.

این prompt خروجی را کنترل می‌کند تا:
- بازنویسی محتوا اتفاق نیفتد
- صرفاً اصلاح انجام شود
- خروجی بدون توضیح اضافی برگردد

### 4.5 نکات و محدودیت‌ها
- LLM وابسته به شبکه/سرویس خارجی است (تاخیر/هزینه/عدم دسترس‌پذیری).
- Nevise برای خطاهای معنایی پیچیده محدودتر از LLM است.
- پیشنهاد توسعه: اضافه شدن معیار «میزان تغییرات» و سطح اصلاح (املایی/نگارشی/هر دو).

## 5. ماژول طبقه‌بندی متن (Text Classification)

### 5.1 هدف
این ماژول برای برچسب‌گذاری خودکار متون فارسی طراحی شده و قابلیت‌های زیر را ارائه می‌دهد:
- آموزش مدل از روی داده کاربر (CSV)
- پیش‌بینی تک‌برچسب
- پیش‌بینی Top-K با امتیاز
- یادگیری افزایشی با افزودن نمونه جدید
- مدیریت مدل‌ها (لیست/حذف) و مدیریت برچسب‌ها (label update)

### 5.2 داده ورودی و کنترل کیفیت داده
ورودی آموزش:
- فایل CSV با حداقل دو ستون (label, text)

پاک‌سازی داده:
- حذف سطرهای تهی و متن‌های خالی
- حذف کلاس‌های کم‌نمونه با شرط `MIN_SAMPLES_PER_CLASS = 5`
- الزام حداقل دو کلاس برای آموزش (برای جلوگیری از مدل تک‌کلاسه)

### 5.3 پیش‌پردازش فارسی (برای TF-IDF)
در روش TF-IDF از Hazm استفاده می‌شود:
- Normalizer → Tokenize → Stopword Removal → Stemming

این مرحله باعث کاهش نویز و بهبود کیفیت featureها می‌شود.

### 5.4 روش‌های آموزشی

#### 5.4.1 TF-IDF + SGDClassifier
- ویژگی‌سازی با `TfidfVectorizer` (پیش‌فرض)
- طبقه‌بند: `SGDClassifier(loss="log_loss")`
- آموزش افزایشی: `partial_fit`
- فایل‌های ذخیره‌شده:
  - `classification_models/<model>.joblib`
  - `classification_models/<model>_vectorizer.joblib`
  - `classification_models/<model>_data.pkl`

#### 5.4.2 SBERT + SGDClassifier
- مدل embedding: `HooshvareLab/distilbert-fa-zwnj-base`
- تولید embedding با `SentenceTransformer.encode`
- آموزش طبقه‌بند خطی با `SGDClassifier(loss="log_loss")`
- فایل‌های ذخیره‌شده:
  - `classification_models/<model>_sbert.joblib`
  - `classification_models/<model>_clf.joblib`
  - `classification_models/<model>_data.pkl`

### 5.5 متادیتا و رجیستری مدل‌ها
فایل `classification_models/metadata.json` شامل:
- `type`: tfidf یا sbert
- `description`
- `created_at`
- `classes`

این ساختار، مدیریت چندین مدل و ارائه endpointهای مدیریتی را تسهیل می‌کند.

### 5.6 APIهای اصلی
- آموزش:
  - `POST /train/tfidf`
  - `POST /train/sbert`
- پیش‌بینی:
  - `POST /predict`
  - `POST /predict/top-k` (با `k` و `threshold`)
- یادگیری افزایشی:
  - `POST /train/add-sample`
- مدیریت:
  - `GET /models`
  - `DELETE /models/{model_name}`
  - `POST /labels/update`

### 5.7 نکات و محدودیت‌ها
- Top-K نیازمند `predict_proba` است (در غیر این صورت خطا بازگردانده می‌شود).
- روش TF-IDF نسبت به SBERT در درک معنایی ضعیف‌تر اما سبک‌تر است.
- پیشنهاد توسعه: اضافه شدن endpoint ارزیابی (F1/Confusion Matrix) و گزارش train/test split.

## 6. ماژول استخراج دامنه‌محور کلمات کلیدی (Domain-based Keyword Extraction)

### 6.1 هدف
این ماژول امکان تعریف یک **دامنه (Domain)** با مجموعه‌ای از کلیدواژه‌ها را فراهم می‌کند و سپس متن ورودی را نسبت به آن دامنه تحلیل کرده و:
- عبارات کلیدی متن
- کلیدواژه‌های match شده
- امتیاز شباهت و امتیاز نهایی هر کلیدواژه
را برمی‌گرداند.

### 6.2 ذخیره‌سازی دامنه‌ها
هر domain در مسیر `DATA_PATH` ذخیره می‌شود:
- `DATA_PATH/<domain>.pkl`

محتوا:
- `keywords`
- `embeddings` (بردار هر keyword)

### 6.3 embedding و شباهت
برای تولید embedding از `SentenceTransformer` به صورت offline استفاده شده است (مدل cached محلی).  
بردارها نرمال‌سازی می‌شوند و شباهت با cosine similarity محاسبه می‌گردد.

### 6.4 فرآیند جستجو
مراحل:
1) پیش‌پردازش متن (حذف علائم، حذف stopwords از `settings.STOPWORDS`)
2) استخراج عبارات کلیدی متن (`extract_keywords`)
3) برای هر عبارت:
   - پیدا کردن نزدیک‌ترین keyword در domain با بیشترین cosine similarity
   - اعمال آستانه `threshold` (پیش‌فرض 0.5)
4) محاسبه امتیاز نهایی هر keyword بر اساس فراوانی match

### 6.5 API
- `POST /add_domain`
- `POST /add_keyword`
- `GET /list_domains`
- `DELETE /delete_domain/{domain_name}`
- `POST /search`

### 6.6 نکته مهندسی
در کد فعلی `keyword_extractor.py` تکرار `embedding.py` است و بهتر است در نسخه بعدی:
- embedding فقط در یک ماژول مشترک نگهداری شود
- keyword_extractor واقعاً مسئول استخراج keyword از متن (TF-IDF/RAKE/KeyBERT/Rules) باشد

## 7. ماژول خلاصه‌سازی متن (Summarization)

### 7.1 هدف
هدف ماژول Summarization ارائه خلاصه‌ای مفهومی و خوانا از متن است تا کاربر بتواند بدون مطالعه کامل سند، اطلاعات کلیدی را دریافت کند.

### 7.2 رویکردهای در نظر گرفته‌شده/پیاده‌سازی‌شده (طبق لاگ توسعه)
- روش ساده (Rule-based)
- روش آماری (TextRank)
- روش مبتنی بر مدل‌های زبانی (LLM-based)
- روش مبتنی بر مدل HuggingFace محلی

### 7.3 تصمیم طراحی: جایگزینی Mistral-7B با mT5 XLSum
طبق یادداشت‌های توسعه، مدل **Mistral-7B-v0.1** به دلیل gated بودن و نیاز به توکن دسترسی، با مدل عمومی‌تر
`csebuetnlp/mT5_multilingual_XLSum`
جایگزین شده است. دلایل اصلی:
- حذف نیاز به احراز هویت
- مناسب برای خلاصه‌سازی چندزبانه (فارسی/انگلیسی)
- سبک‌تر و قابل اجرا روی منابع محدودتر
- طراحی‌شده برای task خلاصه‌سازی (XLSum)

### 7.4 پردازش متن طولانی (Chunking)
در پروژه برای جلوگیری از قطع جمله‌ها:
- متن بر اساس تعداد کلمات به بخش‌های منطقی تقسیم می‌شود
- برای هر بخش خلاصه تولید و در انتها ترکیب می‌شود
- الگوریتم `clean_summary` برای اطمینان از پایان صحیح جملات اعمال می‌گردد

> توجه: جزئیات دقیق پیاده‌سازی Summarization (routes/services و کدهای chunking/clean_summary) در اطلاعات فعلی به‌صورت کد ارائه نشده و در نسخه بعدی گزارش با دریافت کد تکمیل خواهد شد.

## 8. ماژول OCR (Optical Character Recognition)

### 8.1 هدف
تبدیل اسناد غیرقابل‌ویرایش (تصویر/PDF اسکن‌شده) به متن قابل پردازش و آماده‌سازی برای سایر ماژول‌های NLP.

### 8.2 ورودی‌های پشتیبانی‌شده
- تصاویر (PNG/JPG/JPEG/BMP/TIFF)
- PDF (تصویری/اسکن‌شده)
- TXT

### 8.3 روند پردازش
- تصویر: تبدیل به grayscale و اجرای `pytesseract` با `fas+eng`
- PDF: تبدیل صفحات به تصویر با `pdf2image` و OCR صفحه‌به‌صفحه
- برای جلوگیری از پردازش سنگین، preview تعداد صفحات قابل کنترل است.

### 8.4 پاک‌سازی متن OCR با LLM
به منظور حذف نویز OCR و استانداردسازی فاصله‌ها و ZWNJ، ماژول پاک‌سازی متن با اتصال به LLM طراحی شده است تا متن خروجی خواناتر و قابل تحلیل‌تر باشد.

## 9. یکپارچه‌سازی Workflowها

طبق طراحی سرویس، مسیرهایی مانند `/letter-to-summary` یک pipeline کامل را اجرا می‌کنند:
1) دریافت فایل
2) استخراج متن (OCR)
3) اصلاح متن (در حالت advanced)
4) خلاصه‌سازی
5) ارائه خروجی ساختاریافته

خروجی نهایی می‌تواند شامل:
- متن استخراج‌شده
- متن اصلاح‌شده (اختیاری)
- خلاصه
- متادیتای فایل و کیفیت انتخاب‌شده

## 11. نتیجه‌گیری (Conclusion)
در این پروژه یک سرویس ماژولار NLP برای زبان فارسی طراحی و پیاده‌سازی شده است که قابلیت‌های کلیدی از جمله اصلاح متن، طبقه‌بندی، استخراج دامنه‌محور، OCR و خلاصه‌سازی را در قالب API ارائه می‌دهد. مدیریت پیکربندی مبتنی بر محیط اجرا (dev/prod)، طراحی رجیستری برای مدل‌های طبقه‌بندی، و استفاده هم‌زمان از مدل‌های لوکال و LLM، باعث شده سیستم علاوه بر توسعه‌پذیری، قابلیت استقرار و نگهداری مناسبی داشته باشد.

با تکمیل بخش کدهای Summarization و بخش ورودی‌های DOCX/PDF text-extraction، گزارش می‌تواند در نسخه بعدی شامل جزئیات دقیق‌تر پیاده‌سازی و ارزیابی‌های کمی نیز گردد.
